## 判断方法

判断用户当前处于哪个阶段：

| 用户的行为 | 等级 | 典型场景 |
|-----------|------|---------|
| 简单提问，无需工具 | L0 | 问时间、打招呼 |
| 获取信息，无需推理 | L1 | 查看文件、搜索、列出目录 |
| 需要分析/理解/评估/规划 | L2 | 分析架构、比较方案、诊断问题 |
| 想执行某个操作 | L3 | 创建配置、修复 bug、部署服务 |
| 确认执行已有方案 | L4 | 好的、同意、执行吧 |

---

## 各等级详细说明

### L0 - 简单问答
用户想知道一个固定事实，不需要任何工具。

- ✅ "现在几点了" → L0（事实查询）
- ✅ "你好" → L0（问候）
- ⚠️ "你看这个对不对" → L2（需要判断）

### L1 - 只读查询
用户只想获取信息，不改变系统状态。

- ✅ "查看文件内容" → L1（只读）
- ✅ "搜索关键词" → L1（查找信息）
- ⚠️ "查询结果并分析" → L2（含分析意图）

### L2 - 思考分析
用户需要深度理解、推理、判断或规划。即便消息中同时出现查询动词，以分析意图优先。

- ✅ "分析系统架构" → L2
- ✅ "比较两个方案" → L2
- ✅ "查看日志找出问题" → L2（"找出"隐含分析）
- ✅ "诊断这个错误" → L2
- ⚠️ "创建配置文件并分析其结构" → L3（执行优先，含创建）

### L3 - 执行操作
用户明确想执行某个操作。AI 先生成方案，等用户确认后再执行。

- ✅ "创建配置文件" → L3
- ✅ "修复bug" → L3
- ✅ "fix this issue" → L3（英文执行意图）
- ✅ "生成报告" → L3（生成=执行）
- ⚠️ "好的，修复这个" → 按新任务判断，不是L4

### L4 - 确认执行
用户确认执行已有方案。核心特征：短句 + 肯定语气，无新任务内容。

| 类型 | 示例 | 判断 |
|------|------|------|
| 纯确认词 | "好的""同意""执行""开始" | ✅ L4 |
| 短句+确认词 | "确认执行""开始吧" | ✅ L4 |
| 确认+新任务 | "好的，帮我分析一下" | ❌ 按新任务判 |
| 描述执行方式 | "同意后执行""确认后实施" | ❌ 非L4 |
| 长句+确认 | "执行这个方案" | ❌ 有具体对象→L3 |

## 辅助字段判定

### write_operation
- L4 阶段 → true（实际执行方案，会写入系统）
- L0-L3 → false（只读、分析、出方案，不实际写入）

### code_guidance
用户在讨论代码实现细节（函数、算法、调试）→ true
讨论配置、项目结构、方案规划 → false

### agent_pool
用户明确要求并行/同时/批量处理多个任务 → true
大多数单一任务 → false

### self_improving
用户说"记住/纠正/下次/学习/改进" → true
常规任务 → false

### workflow_name
工作流已由本地检测拦截，Ollama 路径始终填 false。
